# 1. What Is MITRE ATT&CK?

## Definition

MITRE ATT&CK is a knowledge base that documents:

- Real-world attacker behaviors
    
- Techniques
    
- Tactics
    
- Procedures
    
- Detection opportunities
    

It answers:

> "How do attackers actually operate?"

---

Traditional security:

```
Malware Found
      |
      |
Remove Malware
```

ATT&CK-based security:

```
Malware Found

      ↓

What behavior occurred?

      ↓

What technique was used?

      ↓

How do we detect it?

      ↓

How do we prevent it?
```

---

# 2. ATT&CK Structure

MITRE ATT&CK is organized into:

## Tactics

The attacker goal.

Examples:

- Initial Access
    
- Persistence
    
- Privilege Escalation
    
- Discovery
    
- Collection
    
- Command and Control
    
- Exfiltration
    

---

## Techniques

The method used.

Example:

Tactic:

```
Collection
```

Technique:

```
SMS Message Collection
```

---

## Procedures

Specific examples of how attackers perform the technique.

Example:

```
Android malware reads SMS database
```

# 4. Mobile Initial Access Techniques

## Technique: Phishing

### Goal

Trick users into installing malicious applications or revealing credentials.

---

Examples:

Fake:

- Banking apps
    
- VPN apps
    
- Security updates
    
- Games
    

---

Indicators:

- Unknown APK source
    
- Suspicious links
    
- Fake developer names
    

---

Detection:

MDM:

```
Unknown application installed
```

EDR:

```
Suspicious package behavior
```

---

# 5. Malicious Application Installation

## Technique

Attackers distribute:

- Modified APK files
    
- Trojan applications
    
- Fake updates
    

---

Example:

Legitimate:

```
weather.apk
```

Modified:

```
weather_pro_update.apk
```

Contains:

```
Remote access capability
```

---

Detection:

Check:

- Application source
    
- Signature
    
- Permissions
    
- Behavior
    

---

# 6. Persistence Techniques

Attackers want malware to survive:

- Reboots
    
- User activity
    
- Updates
    

---

## Background Services

Example:

Application starts:

```
Device Boot

      ↓

Background Service Starts

      ↓

Malware Active
```

---

Indicators:

- Unknown services
    
- Constant background activity
    
- Battery drain
    

---

Detection:

ADB:

```bash
adb shell dumpsys activity services
```

---

# 7. Privilege Escalation

## Goal

Gain more control over the device.

---

Examples:

- Exploiting vulnerabilities
    
- Rooting Android
    
- Abusing accessibility services
    

---

## Root Access

Normal:

```
Application

      ↓

Android Permission Model
```

Compromised:

```
Application

      ↓

Root Access

      ↓

Full Device Control
```

---

Detection:

Look for:

- Root binaries
    
- Modified system files
    
- Security policy changes
    

---

# 8. Permission Abuse

One of the most important mobile attack techniques.

---

Example:

Application:

```
Calculator App
```

Requests:

```
READ_SMS
CAMERA
MICROPHONE
CONTACTS
LOCATION
```

---

Question:

Does functionality justify permission?

---

Risky Permissions:

|Permission|Risk|
|---|---|
|SMS|Message theft|
|Contacts|Target discovery|
|Microphone|Surveillance|
|Camera|Recording|
|Location|Tracking|
|Accessibility|Credential theft|

---

# 9. Discovery Techniques

Attackers gather information.

---

## Application Discovery

Attackers identify:

- Installed applications
    
- Security software
    
- Banking apps
    

---

Why?

To determine:

- Available targets
    
- Defensive tools
    
- Environment information
    

---

Example:

Malware checks:

```
Is banking app installed?
```

If yes:

```
Activate credential theft
```

# 11. Command and Control (C2)

After compromise, malware needs communication.

---

Typical flow:

```
Mobile Malware

       |

       |

Internet

       |

       |

Attacker Server
```

---

Indicators:

- Unknown domains
    
- Repeated connections
    
- Encrypted traffic
    
- Beaconing
    

---

Example:

Every 60 seconds:

```
Device → Unknown Server
```

# Knowledge Check

## Question 1

What is MITRE ATT&CK?

### Answer:

A framework documenting real-world attacker behaviors and techniques.

---

## Question 2

Why do defenders use ATT&CK?

### Answer:

To understand attacker behavior, improve detection, and create defensive controls.

---

## Question 3

Does installing an unknown application prove malware?

### Answer:

No.

It is an indicator requiring investigation.

---

## Question 4

Why are permissions important?

### Answer:

They reveal what resources an application can access and help identify suspicious behavior.

---

# Daily Reflection

## 1. Why is behavior mapping better than simply identifying malware names?

Because attackers constantly modify malware. Behavior patterns remain more consistent.

---

## 2. Which mobile behaviors are most concerning?

Highest concern:

- SMS access
    
- Accessibility abuse
    
- Credential theft
    
- Data exfiltration
    
- Persistence
    
- Unknown C2 communication
    

---

## 3. Why should defenders understand attacker techniques?

Understanding techniques allows defenders to detect attacks even when specific malware samples are unknown.

---

## 4. How would you prioritize a mobile incident?

Priority:

1. Active data theft
    
2. Credential compromise
    
3. Command-and-control communication
    
4. Persistence
    
5. Suspicious permissions
    
6. Performance issues
