# Case Study 1 — Pegasus Spyware

## Overview

Pegasus is a mobile spyware platform associated with highly advanced targeted attacks.

It has been used against:

- Journalists
    
- Government officials
    
- Activists
    
- Business leaders
    

---

# Attack Goal

The attacker attempts to obtain:

- Messages
    
- Calls
    
- Location data
    
- Microphone recordings
    
- Camera access
    
- Contacts
    

---

# Attack Method

Historically, Pegasus campaigns used:

- Zero-click exploits
    
- Malicious links
    
- Exploitation of messaging applications
    

---

# Zero-Click Attack

A zero-click attack requires:

NO user interaction.

Example:

```text
Attacker sends malicious message
          |
          ↓
Messaging application processes message
          |
          ↓
Vulnerability exploited
          |
          ↓
Spyware installed
```

---

# Why Zero-Click Attacks Are Dangerous

Traditional malware requires:

```text
User downloads file
User installs application
User grants permissions
```

Zero-click:

```text
No user action required
```

---

# Data Collected

Possible spyware capabilities:

## Communication

- SMS
    
- Emails
    
- Chat messages
    

---

## Surveillance

- Microphone
    
- Camera
    
- Location
    

---

## Device Information

- Contacts
    
- Files
    
- Device identifiers
    

---

# Indicators of Compromise

Possible indicators:

## Battery

- Increased drain
    
- Device overheating
    

---

## Network

- Unknown outbound connections
    

---

## System

- Unexpected crashes
    
- Strange behavior
    

---

# Defender Response

Actions:

1. Collect forensic evidence
    
2. Update device
    
3. Remove compromised software
    
4. Reset credentials
    
5. Replace device if necessary
    

---

# MITRE ATT&CK Mobile Mapping

## Technique:

### Exploitation for Client Execution

Purpose:

Attacker abuses software vulnerabilities.

---

# Defensive Controls

Controls:

✅ Keep OS updated  
✅ Enable application security controls  
✅ Use MDM  
✅ Monitor network traffic  
✅ Use mobile threat defense tools

# Case Study 2 — Malicious Android Application

## Scenario

A user downloads:

```
Free Weather Application
```

from an unofficial website.

---

# Application Behavior

The app requests:

```
Location
Contacts
SMS
Microphone
Storage
```

---

# User Action

User clicks:

```
Allow All Permissions
```

---

# Attack Flow

```text
Fake application downloaded
            |
            ↓
User installs APK
            |
            ↓
Permissions granted
            |
            ↓
Application runs background service
            |
            ↓
Data collected
            |
            ↓
Information sent to attacker
```

---

# Abused Permissions

## SMS Permission

Potential abuse:

- Read messages
    
- Steal authentication codes
    
- Send messages
    

---

## Contacts Permission

Potential abuse:

- Collect contacts
    
- Spam campaigns
    
- Social engineering
    

---

## Location Permission

Potential abuse:

- Tracking
    
- Surveillance
    

---

## Microphone Permission

Potential abuse:

- Audio recording
    

---

# Investigation Steps

## Step 1 — Application Inventory

Command:

```bash
adb shell pm list packages
```

Look for:

- Unknown packages
    
- Recently installed apps
    

---

## Step 2 — Analyze Permissions

Command:

```bash
adb shell dumpsys package package.name
```

Review:

- Permissions
    
- Services
    
- Receivers
    

---

## Step 3 — Check Processes

Command:

```bash
adb shell ps
```

Look for:

- Unknown background processes
    

---

## Step 4 — Network Analysis

Look for:

- Unknown servers
    
- Large uploads
    

---

# Defensive Actions

Remove application:

```bash
adb uninstall package.name
```

Reset:

- Passwords
    
- Tokens
    
- Accounts

# Case Study 3 — Banking Trojan

## Overview

Mobile banking malware attempts to steal:

- Banking credentials
    
- Authentication codes
    
- Payment information
    

---

# Common Delivery Methods

## Phishing SMS

Example:

```
Your bank account is locked.
Verify here:
malicious-link.com
```

---

## Fake Banking Applications

Example:

Real:

```
com.bank.mobile
```

Fake:

```
com.bank.security.update
```

---

# Attack Techniques

## Overlay Attacks

The malware displays:

```
Fake login screen
```

over the real banking application.

---

# Attack Flow

```text
User opens banking app

        ↓

Malware displays fake login page

        ↓

User enters credentials

        ↓

Credentials sent to attacker
```

---

# Indicators

Look for:

- Unknown accessibility permissions
    
- Unknown applications
    
- Strange login activity
    
- Unauthorized transactions
    

---

# Defender Actions

Check:

Accessibility Services:

```
Settings
 ↓
Accessibility
 ↓
Installed Services
```

Remove:

Unknown services.

---

# MITRE ATT&CK Mobile Mapping

## Technique:

### Input Capture

Attacker captures user input.

# Knowledge Check

## Question 1

Why are permissions important during mobile investigations?

Answer:

Because permissions reveal what access an application has and whether that access matches the application's purpose.

---

## Question 2

What makes zero-click attacks dangerous?

Answer:

They require no user interaction, making detection and prevention more difficult.

---

## Question 3

Why are enterprise mobile devices valuable targets?

Answer:

Because they often contain:

- Corporate email
    
- Credentials
    
- VPN access
    
- Sensitive documents
    
- MFA tokens
    

---

## Question 4

What is an overlay attack?

Answer:

A technique where malware displays a fake interface over a legitimate application to steal user input.
