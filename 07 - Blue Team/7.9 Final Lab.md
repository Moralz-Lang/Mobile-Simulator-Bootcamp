# Final Blue Team Investigation Lab

## Objective

This capstone lab combines everything learned throughout the Blue Team module into one realistic investigation.

You will investigate a potentially compromised Android device by:

- Identifying suspicious behavior
    
- Collecting forensic evidence
    
- Analyzing permissions
    
- Reviewing installed applications
    
- Examining running services
    
- Looking for persistence
    
- Assessing network activity
    
- Mapping findings to MITRE ATT&CK
    
- Producing an incident report
    

This mirrors the workflow of a real Mobile Incident Response (Mobile IR) analyst.

---

# Learning Objectives

After completing this lab you should be able to:

- Perform a structured mobile investigation
    
- Collect evidence safely
    
- Differentiate benign from malicious behavior
    
- Build an evidence timeline
    
- Identify Indicators of Compromise (IoCs)
    
- Produce a professional investigation report
    

---

# Scenario

You are a Mobile Security Analyst.

An employee contacts the SOC.

They report:

- Battery drains much faster
    
- Device feels slower
    
- Contacts disappear occasionally
    
- Mobile data usage increased dramatically
    
- Pop-up advertisements appear randomly
    
- Camera LED briefly activates
    
- SMS messages appear sent without user knowledge
    

The employee recently installed:

> "Weather Ultra Pro"

from an unofficial APK website.

---

# Investigation Rules

Do NOT jump to conclusions.

Treat every indicator as:

> Suspicious

NOT

> Proof of malware

Follow the investigation process.

# Phase 1 — Initial Triage

Collect basic information.

---

## Device Information

```bash
adb shell getprop
```

Questions

- Android version?
    
- Security patch level?
    
- Manufacturer?
    
- Build fingerprint?
    

---

## Storage

```bash

```

# Phase 12 — Recommended Actions

Example response plan.

Immediate

- Disconnect device
    
- Preserve evidence
    
- Notify SOC
    

Containment

- Disable application
    
- Block domains
    
- Block IPs
    

Investigation

- Extract APK
    
- Reverse engineer APK
    
- Compare hash
    
- Search VirusTotal
    
- Review MDM logs
    

Recovery

- Remove malware
    
- Reset credentials
    
- Factory reset if necessary
    

Lessons Learned

- Improve user awareness
    
- Restrict sideloading
    
- Strengthen MDM policies

# Capstone Knowledge Check

### 1. What is the first priority during a suspected mobile compromise?

A. Delete the application immediately

B. Preserve evidence while containing risk

C. Factory reset the phone

D. Install another antivirus

**Answer:** **B**

---

### 2. Which combination provides the strongest evidence of compromise?

A. Battery drain only

B. One suspicious permission

C. High CPU usage only

D. Multiple correlated indicators (permissions, persistence, network activity, logs, and unusual behavior)

**Answer:** **D**

---

### 3. Why is MITRE ATT&CK useful during investigations?

A. It identifies malware automatically

B. It maps observed behaviors to known adversary techniques, helping analysts communicate findings consistently

C. It blocks attacks

D. It replaces forensic analysis

**Answer:** **B**

---

### 4. Which artifact is most useful for reconstructing what happened over time?

A. Device wallpaper

B. Timeline built from logs, process activity, installation history, and network events

C. Battery percentage alone

D. Screen brightness settings

**Answer:** **B**

---

### 5. After confirming a malicious application, what is the best next step?

A. Quietly ignore it

B. Preserve evidence, contain the threat, eradicate the malware, recover the device, and document lessons learned

C. Only uninstall the application

D. Reboot the phone repeatedly

**Answer:** **B**
