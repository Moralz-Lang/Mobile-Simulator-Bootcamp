# 1. What Is Mobile Incident Response?

Mobile Incident Response (MIR) is the structured process used to:

- Detect
    
- Analyze
    
- Contain
    
- Eradicate
    
- Recover from
    

security incidents involving mobile devices.

Mobile incidents may include:

- Malware infections
    
- Credential theft
    
- Unauthorized applications
    
- Data leakage
    
- Lost/stolen devices
    
- Spyware
    
- Phishing attacks
    
- Malicious configuration profiles
    
- Compromised enterprise applications
    

---

# Phase 1 — Preparation

## Goal

Build the capability to respond before an incident occurs.

---

## Preparation Activities

Organizations should have:

### Mobile Device Management (MDM)

Examples:

- Microsoft Intune
    
- VMware Workspace ONE
    
- Jamf
    

Purpose:

- Enforce policies
    
- Deploy applications
    
- Monitor devices
    
- Remote wipe devices
    

---

### Security Policies

Examples:

Password requirements:

```
Minimum 12 characters
Biometric authentication enabled
Auto-lock enabled
```

Application policies:

```
Only approved applications allowed
Unknown sources disabled
```

Network policies:

```
VPN required
Certificate authentication
```

## Goal

---

## Immediate Actions


Actions:

- Tokens
    
- Sessions
    

Revoke:

- OAuth tokens
    
- API keys
    
- Certificates

# Phase 4 — Evidence Collection

## Important Rule

Do not immediately wipe the device.

Evidence may be lost.

---

# Android Evidence Collection

## Device Information

```bash
adb shell getprop
```

Collect:

- Android version
    
- Device model
    
- Build information
    

---

## Installed Applications

```bash
adb shell pm list packages
```

Example:

Output:

```
package:com.android.chrome
package:com.weather.app
package:com.fake.update
```

Investigate:

- Unknown packages
    
- Recently installed applications
    
- Suspicious names
    

---

# Application Information

Get package details:

```bash
adb shell dumpsys package package.name
```

Example:

```bash
adb shell dumpsys package com.fake.app
```

Look for:

- Permissions
    
- Installation date
    
- Components
    
- Services
    

---

# Running Processes

Command:

```bash
adb shell ps
```

Look for:

Unexpected processes:

```
unknown_service
background_agent
hidden_update
```

---

# Running Services

Command:

```bash
adb shell dumpsys activity services
```

Investigate:

- Background services
    
- Unknown applications
    
- Persistent components
    

---

# Network Investigation

## Connections

```bash
adb shell netstat
```

Look for:

Suspicious:

```
Unknown IP
Unusual ports
Repeated connections
```

---

# Logs

Android logs:

```bash
adb logcat
```

Export:

```bash
adb logcat > device_logs.txt
```

Analyze:

- Application crashes
    
- Permission failures
    
- Suspicious activity
    

---

# Phase 5 — Eradication

## Goal

Remove the threat.

---

Actions:

## Remove malicious applications

Example:

```bash
adb uninstall package.name
```

---

## Remove suspicious accounts

Check:

```
Settings
↓
Accounts
```

Look for:

- Unknown accounts
    
- Corporate accounts
    
- Certificates
    

---

## Update Device

Install:

- Security patches
    
- OS updates
    
- Application updates
    

---

# Phase 6 — Recovery

Goal:

Return device to normal operation.

---

Recovery actions:

- Restore backups
    
- Re-enroll device into MDM
    
- Verify security settings
    
- Monitor activity

# Knowledge Check

## Question 1

What is the purpose of incident response?

### Answer:

To identify, contain, remove, and recover from security incidents.

---

## Question 2

Why should investigators avoid immediately wiping a device?

### Answer:

Because wiping destroys evidence needed for investigation.

---

## Question 3

Which command lists installed Android packages?

### Answer:

```bash
adb shell pm list packages
```

---

## Question 4

Why are permissions important during investigations?

### Answer:

Because excessive or unnecessary permissions can reveal malicious behavior.
